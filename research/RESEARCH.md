# EvoSnap Research Module — Self-Trained Material Classifier

## Motivation

EvoSnap's pipeline uses a hosted vision-language model (VLM) for open-world
object understanding. VLMs are powerful but (a) require internet, (b) are
non-deterministic, and (c) give no reproducible accuracy figure. For the
environmental core of the app — *what material is this object, and is it
recyclable?* — we trained our own supervised classifier so that every scan
carries a second, fully local, measurable prediction.

This mirrors a production pattern called **model ensembling / cross-checking**:
a small specialist model validates a large generalist one. When the two agree,
confidence in the material analysis rises; when they disagree, the UI can flag
uncertainty.

## Dataset

**TrashNet** (Yang & Thung, Stanford CS229, 2016): 2,527 photographs of waste
items on a white background across six recycling categories:

| class | images |
|---|---|
| paper | 594 |
| glass | 501 |
| plastic | 482 |
| metal | 410 |
| cardboard | 403 |
| trash (non-recyclable) | 137 |

Split: 80% train / 20% validation, shuffled with a fixed seed (42) for
reproducibility.

## Method

- **Architecture:** MobileNetV3-Small pre-trained on ImageNet (~2.5M params,
  chosen for CPU/edge inference speed — the same class of network that ships
  on phones).
- **Transfer learning:** the convolutional feature extractor is frozen except
  the last three blocks; the classification head is replaced with a 6-way
  linear layer. This trains ~15% of the weights, which prevents overfitting on
  a 2.5k-image dataset.
- **Augmentation:** random resized crops (0.7–1.0), horizontal flips, ±12°
  rotation, color jitter — simulating the varied angles/lighting of real
  phone captures.
- **Optimization:** AdamW (lr 1e-3, weight decay 1e-4), cosine annealing,
  label smoothing 0.05, 6 epochs, batch 32.
- **Export:** best checkpoint exported to **ONNX** (opset 13) so the backend
  serves it with `onnxruntime` — no PyTorch needed at inference time.

Run it yourself:

```bash
cd research
pip install torch torchvision onnx pillow numpy
python train_material_classifier.py --epochs 6
```

## Results

Generated by the training script into `research/results/`:

- `metrics.json` — validation accuracy and per-class precision/recall
- `confusion_matrix.txt` — 6×6 confusion matrix (rows = actual)
- `training_log.txt` — full training trace

Typical validation accuracy for this setup is **~88–93%**, with most confusion
between glass/plastic (transparent objects) and paper/cardboard — an expected
and explainable failure mode worth discussing in the report.

## Integration

`backend/services/material_classifier.py` loads the ONNX model at server
start. Every `/api/scan` runs the classifier on the captured frame (~20 ms on
CPU) and attaches:

```json
{ "ml_material": "plastic", "ml_confidence": 0.87 }
```

The app displays this as an "ON-DEVICE MODEL" card next to the VLM's material
analysis, so users see both the generalist and the specialist opinion.

## Limitations & future work

- TrashNet images are single objects on white backgrounds; real scans have
  clutter. Fine-tuning on frames collected through EvoSnap itself
  (active learning) is the natural next step.
- 6 classes is coarse — subdividing plastics by resin code (PET/HDPE/PP…)
  would make recycling advice actionable.
- The ONNX model is small enough (~6 MB) to embed **in the app itself** with
  onnxruntime-mobile, enabling fully offline material detection.
